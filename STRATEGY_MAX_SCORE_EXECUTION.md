Дедлайн сдачи по FAQ: 30 сентября 2026, 12:00 МСК.

## Итог аудита

Проект представляет собой работающий MVP: мини-приложение MAX, студенческий путь, Career GPS, объяснимый подбор возможностей, база знаний с безопасным fallback, административная панель и backend с MAX-адаптером. Пользователь подтвердил ручную проверку мини-приложения в MAX. На проверке 24 сентября сайт и `/api/health/` по указанному HTTPS-адресу ответили `200`, API вернул `status: ok`.

**Максимум пока не подтверждён по четырём объективным причинам:**

1. `DATA-API.yaml` всё ещё указывает на выключенный ngrok-домен, хотя текущий рабочий адрес — `https://188-120-251-143.sslip.io`. Файл ранее прошёл официальный структурный валидатор с кодом `0`; нужно обновить URL и повторить проверку.
2. Последний сохранённый API smoke (`output/reports/MAX-smoke.txt`) выполнялся в `mock`-режиме. Он подтверждает локальное создание уведомления со статусом `simulated`, но не реальную доставку в MAX.
3. Не проверена end-to-end цепочка: студент подписывается на тему → администратор публикует подходящую возможность → студент получает сообщение в MAX → кнопка открывает именно эту возможность → повторная публикация не создаёт дубль.
4. По продуктовой оценке есть сильный сценарий, но для максимума нужны прямые доказательства потребности пользователей и более конкретный план пилота и тиражирования. ТЗ презентации предусматривает эти блоки; презентацию готовит назначенный человек, отдельный агент для неё не нужен.

Код уже содержит основы целевого MAX-сценария: отправку сообщения, кнопку `open_app`, payload `opportunity_<id>`, разбор launch-параметра и переход на карточку возможности. Поэтому сначала проверяем и доводим существующую ценную функцию, а не добавляем боту случайные команды ради количества.

## Цели по критериям

Критерии онлайн-этапа: продуктовая оценка — 40%, техническая — 60%. MAX-бонус `+0,15` начисляется только при полном выполнении его условий. Итоговая презентация и финальная защита остаются ответственностью назначенного участника команды.

| Область | Что уже есть | Что нужно подтвердить для максимума |
|---|---|---|
| Пользовательская ценность | Студенческий карьерный навигатор и связный основной сценарий | Прямое подтверждение потребности студентов; преимущество перед текущим способом поиска; конкретный результат пользователя |
| Масштабирование | Университетский tenant-контекст и описание архитектурного пути | Конкретный первый пилот, процесс подключения следующей организации, необходимые данные, владельцы, ресурсы и ограничения |
| UX/UI | Пользователь сообщает, что mini app в MAX открывается и данные видны | Сценарий без тупиков, понятные загрузка/ошибки/успех и доказательство возврата по уведомлению к нужной карточке |
| Основной функционал | Локальный smoke проходит в mock-режиме; функции MVP реализованы | Повторный прогон полного пользовательского сценария на доступной среде и зафиксированной версии |
| MAX-интеграция и обмен данными | Real adapter, подписки, уведомления и формирование `open_app` предусмотрены в коде | Реальная доставка сообщения, правильный пользователь и возможность, корректный возврат, отсутствие дублей |
| Архитектура и безопасность | Модульный монолит, разграничение ролей, `.env` игнорируется Git, зависимости зафиксированы | Контрольный прогон на сдаваемом commit; не раскрывать секреты в отчётах и артефактах |
| Документация и комплектность | README, OpenAPI, Docker, DATA-API, smoke-сценарий | Актуальный публичный API URL в DATA-API и отчёты, относящиеся к одному commit hash |
| MAX-бонус | Уведомление с возвратом к действию создаёт потенциальную ценность сверх открытия mini app | Реально пройти весь сценарий на тестовом MAX-пользователе и явно показать его в материалах |

Отдельного функционального расширения бота пока не планировать. Реальное уведомление с переходом к релевантной возможности — наиболее целевое расширение: оно связывает MAX-бота с основным сценарием продукта и даёт конкретную пользу. Бонус не считать полученным до проверки и решения жюри.

## Комментарии к запуску

### Волна 1 — параллельно

Запустить агентов **1, 3 и 4**. Они отвечают за разные участки: API-комплект, продуктовую доказательность и UX. Каждый агент заменяет только собственный отчётный блок в этом файле.

### Волна 2 — MAX

Агент **2** может начать ревью кода параллельно с первой волной, но реальную отправку выполнять только после статической проверки, исправлений и подтверждения тестового пользователя. Реальный прогон проводить отдельно, не параллельно с другими API-smoke или публикациями: они тоже могут отправить сообщения.

### Финальная общая проверка

После отчётов:

1. Сверить, что все результаты относятся к одному commit hash.
2. Повторить официальный DATA-API validator после любых изменений в `DATA-API.yaml`/`openapi.yaml`.
3. Один раз пройти единый сценарий: запуск mini app → профиль/цель → Career GPS → подходящая возможность → подписка → публикация администратором → реальное сообщение MAX → `open_app` → правильная карточка → повторная публикация без дубля.
4. Передать человеку, готовящему презентацию, актуальный API URL, commit hash, реальные статусы тестов, скриншоты MAX-сценария, результаты продуктовой проверки и ограничения MVP.
5. Оставить публичный сервис доступным на период оценки; подготовить архив именно проверенного commit и контрольную сумму.
